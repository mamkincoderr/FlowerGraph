# FlowerGraph — CLI handoff

Этот пакет — входная точка для сессии Grok **в CLI**, где есть доступ к скриншотам и локальному репо.

Не читай PDF заново, если эти файлы на месте. Источник правды по задачам:

| Файл | Назначение |
|---|
| `docs/UI_NAV_REVIEW.md` | полный перечень UI-01…UI-46 + приёмка + ручной чек-лист |
| `docs/UI_TASKS.json` | машиночитаемый индекс задач |
| `docs/CLI_HANDOFF.md` | этот бриф |
| вложение / `FlowerGraph_UI_review.pdf` | оригинал ревью (строки по коммиту `352e2d6`) |

## Репозиторий

- GitHub: `mamkincoderr/FlowerGraph`
- База ревью: default branch, commit `352e2d6`
- Версия в коде на базе: `APP_VERSION = '0.7.2.123'` (`ui/main_window.py`)
- Стек: Python 3.11, PySide6, pyqtgraph 0.13.x, numpy
- CI: `.github/workflows/build-and-release.yml`
  - push `main` → unittest + Windows zip + Linux tar
  - tag `v*` → GitHub Release
  - `workflow_dispatch` тоже есть
- Релиз: поднять последнюю компоненту `APP_VERSION`, закоммитить, тег `v<APP_VERSION>`

## Правила работы (из ревью, раздел 0)

1. Порядок: **P0 → P1 → P2 → P3**. Внутри раздела задачи независимы, если не сказано иное.
2. Коммит: `fix(UI-03): …` — ID обязателен.
3. Строки в ревью — по `352e2d6`. После первых правок ориентироваться по **имени метода**.
4. Пункты `[проверить]` — сначала воспроизвести (скрин / консоль), потом править.
5. Не менять формат `.fgd`, протоколы и публичные сигналы источников без необходимости.
6. После блока задач: `python -m pytest tests` (в CI сейчас `python -m unittest discover -s tests -v`) + чек-лист раздела 7.
7. Offscreen-скрин:
   ```bash
   QT_QPA_PLATFORM=offscreen python -c "..."
   # или в живом GUI: widget.grab().save('shot.png')
   ```

## Скриншоты в CLI

Цель: доказать баг и приёмку, не «красивые картинки».

Имена файлов:

```
shots/UI-xx_before_<сцена>.png
shots/UI-xx_after_<сцена>.png
shots/check_<тема>_<WxH>[_scale150].png
```

Минимальный набор сцен (окно 1000×680 и 1920×1080; Win 100%/150% если доступно):

1. Холодный старт, пустая сессия
2. Генератор, 1 канал, амплитуда 1, live + follow
3. Генератор, 4+ канала, «Разнести»
4. Выделение на live-графике → контекстное меню
5. Static блок, зум времени до предела «−»
6. Левая панель, активный канал, кнопки ▲▼
7. Тулбар при ширине 1000 и 1280
8. Экспорт PNG / диалог CSV
9. FG-NET диалог открыт >1 с
10. Тёмная тема ОС (если есть)

Консоль при приёмке UI-01: не должно быть `Ambiguous shortcut overload`.

## Что не трогать без явного запроса

- формат `.fgd`
- протоколы COM / FG-NET, кроме мест, где они ломают UI (UI-34, UI-35, UI-45, UI-46)
- публичные сигналы источников

## Definition of done для CLI-сессии

Сессия считается полезной, если по каждому закрытому UI-xx есть:

- коммит с ID в message, **или** явный статус `wontfix` / `needs-repro` в JSON;
- скрин или лог приёмки;
- тесты не красные.

Не собирать релиз и не ставить тег, пока пользователь не сказал «релиз».
